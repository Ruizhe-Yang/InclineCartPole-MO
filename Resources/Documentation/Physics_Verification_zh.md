# InclineCartPole v0.6 物理建模与验证说明

版本：v0.6.0  
验证日期：2026-11-06  
总体仿真入口：`InclineCartPole.Simulation.CompleteMission`

## 1. 版本目标与验收口径

v0.6 在 v0.5 的四轮斜坡倒立摆模型上完成物理边界修正、车载采集归入本体以及只读关键参数展示。默认工况仍为 10 s，输出间隔 0.01 s，相对容差 `1e-6`。本次实际数值验证采用 **OpenModelica 1.25.5、Modelica Standard Library 4.0.0、DASSL**。

编译模型保留 **61 个连续状态**。四套独立电机及驱动器、绕组电感、电流控制、轮组转动惯量、动态轮地接触、电池 SOC 与极化 RC、母线和辅助电容、设备热容、传感器前端及挡板行程均保留。Acquisition 的层级调整和 Displays 的接入没有用输出曲线或额外积分器替代既有物理状态。

约 1 s 的目标指已编译模型执行 10 s 物理工况的墙钟耗时。编译与链接时间、运行耗时、变量和方程规模、重复运行统计及最终执行选项统一见 [Performance_Report.md](Performance_Report.md)。本说明只报告物理行为和数值敏感性。

代码使用标准 Modelica 方程、连接器与 MSL 4.0.0 部件，保留面向 OpenModelica 的工具注解。**本次没有在 MWorks.Sysplorer 中实际运行，不能将 OpenModelica 的结果表述为 MWorks 实测结果。**

## 2. 真实工作流与部件归属

### 2.1 本体承担完整采集过程

`Mechanical.CartPoleSystem` 直接装配位置编码器、摆角编码器、四个轮载传感器、采样时钟、报文传输及测量替换边界。顶层不再设置 Acquisition 实例，控制器从本体取得 `measurements` 与 `tick`。传感器与动力学真值的连接均保留在本体内部。

采样周期由 `cartPole.transport.samplePeriod` 拥有，默认 **0.01 s**；采样时钟引用这个参数。`cartPole.transport.latency` 默认 **0.0005 s**，表示采样后到报文送达的真实时间间隔。两者分别描述设备采样和通信，不能与结果输出间隔或传感器带宽混用。默认测量年龄最大值为 **10.5 ms**，由 10 ms 采样保持和 0.5 ms 传输共同形成。

控制器的测量许可同时要求实际挡板释放、供电就绪、报文有效、时间顺序正确和测量年龄符合要求。当前 `maxMeasurementAge` 为 0.03 s。年龄从 `sampledAt` 计算，较新的报文到达时刻不能掩盖较旧的测量。

源模型：[CartPoleSystem](../../Mechanical/CartPoleSystem.mo)、[SampledTransport](../../Signals/SampledTransport.mo)、[MeasurementPermit](../../Control/LogicUnits/MeasurementPermit.mo)。

## 3. 本次物理修正

### 3.1 辅助降压电源：按实际电容与负载闭合功率

v0.5 对 5 V 电压施加一阶响应，再用正则化除法计算输入功率。输入母线失电而输出电容仍带电时，强制电压衰减可能与实际电容释放能量、负载耗散不一致。

v0.6 由转换器输出电流、输出电容和负载电流决定输出电压：

```modelica
converterCurrent = if inputAvailable then
  max(0, target/auxiliaryLoadR
    + buckC*(target - V5)/auxiliaryTimeConstant)
  else 0;
loadCurrent = V5/auxiliaryLoadR;
buckC*der(V5) = converterCurrent - loadCurrent;
```

器件导通损耗按 `converterCurrent` 计算。输入不可用时转换电流为零，电容完全通过实际负载放电，时间常数为 `auxiliaryLoadR*buckC`。输入功率、热端口功率与电容储能变化率在实际连接器处闭合。

低输入关断和恢复阈值分别为 **0.5 V、0.6 V**，形成滞回并避免零电压功率除法。这两个值属于平均模型的低压适用边界；系统实际就绪仍由电源监督器判定。`auxiliaryTimeConstant` 表示电流调节中的电压误差时间尺度，实际电压闭环响应同时受电容和负载影响。

该修改保留原有输出电容状态，没有新增 PWM 开关时钟。模型属于平均降压供电模型，未解析功率电感、开关纹波波形、控制芯片复位过程及反向回馈。

源模型：[AuxiliaryLoad](../../Electrical/AuxiliaryLoad.mo)。

### 3.2 传感器：断电后停止模拟前端更新

位置编码器、角度编码器和轮载传感器在未供电期间冻结模拟前端状态，数字输出保持最后一次采样值。恢复供电后，前端从保留状态按本地带宽重新响应，不再利用停电期间持续跟踪的真值。

位置和角度通道的内部速度估计为 `der(frontEnd)`。它是模拟带宽状态的导数，随后与位置或角度同步量化并采样。断电时内部速度估计为零，但最后的数字速度输出仍保持；报文有效性负责阻止控制器把失电数据当作有效测量。

这里保留带宽受限导数估计，没有将速度通道改成数字一阶差分。模型未显式包含实物上电复位、随机噪声与零点漂移，相关参数属于系统级假设。

源模型：[PositionEncoder](../../Signals/PositionEncoder.mo)、[AngleEncoder](../../Signals/AngleEncoder.mo)、[LoadCell](../../Signals/LoadCell.mo)。

### 3.3 端部缓冲器：补全受力高度对轮载的影响

`PlanarCore` 新增 `bufferHeight=0.12 m`，表示端部缓冲器作用点相对轮心的高度。外力矩中增加 `-bufferHeight*bufferForce`，使缓冲力同时进入平动方程和前后轮载平衡。

原有缓冲器刚度、单侧接触、压缩过程阻尼及弹性储能均保留。相同状态、相同缓冲力下，修正改变前后轮的载荷分配，保持总法向力不变。名义工况最大位置约 0.67 m，没有到达 1.18 m 的缓冲器接触位置；本次缓冲器验证采用明确的代数力矩检查，没有将其表述为已完成整机碰撞工况验证。

### 3.4 保持正确的坐标、惯量及挡板能量关系

`s` 沿斜坡向上为正；`theta` 从全局竖直向上方向顺时针计量。`theta=0` 为竖直向上，`theta=pi` 为自然垂下；`beta=theta+alpha` 将杆方向变换到坡面坐标。原有平动、摆动、重力势能与轮载方程的符号保持不变。

轮组的等效动能惯量使用 `Jwheel+Jmotor*gearRatio^2`；整车轮载平衡中的实际角动量变化率使用 `Jwheel+Jmotor*gearRatio`。二者描述不同物理量，保留各自的齿比次幂。

挡板继续采用通电后的过阻尼行程响应。真实行程决定实际释放，接触弹性能及撤出释放的能量进入相应耗散项。该模型没有解析电磁场、动子惯量或横向撤出摩擦，定位为总体任务使用的执行器响应模型。

源模型：[PlanarCore](../../Mechanical/PlanarCore.mo)、[WheelDrive](../../Electrical/WheelDrive.mo)、[ReleaseGate](../../Mechanical/ReleaseGate.mo)。

### 3.5 预充锁存的代数实现

`SupplySupervisor` 使用 `pre(bypassClosed)` 选择预充电阻或旁路电阻，使锁存状态通过事件迭代更新。此改写处理电压判据与网络电阻之间的代数依赖，**不增加物理时间延迟**。最短预充时间、实测电压比、旁路电阻和欠压滞回保持原有含义。

源模型：[SupplySupervisor](../../Electrical/SupplySupervisor.mo)。

### 7.2 适用范围

本模型用于带四轮电驱、设备采集和有限状态控制的斜坡倒立摆系统级分析。当前边界为：

- 刚性斜面与平面运动，车架不建立独立俯仰、侧倾和三维姿态自由度。四轮载荷来自准静态接触约束与角动量平衡。
- 四轮法向力必须为正，杆端不得穿地，小车必须保持在导轨有效范围；违反这些条件时由有效域断言停止计算。模型没有实现车轮离地、车架翻转和杆地碰撞后的连续动力学。
- 轮地接触保留预滑弹性、滑移耗散和滚阻。摩擦容量快速变化时，应同时检查接触力与容量裕量，不能通过无损截断接触力掩盖储能变化。
- 电机驱动使用平均 H 桥及等效纹波损耗，不解析实际 PWM 开关波形；电池采用 MSL 一阶极化 RC 与 SOC 模型。
- 热网络为集总热容与热导，名义 10 s 结果不构成长期温升或实物热保护的验证。
- 传感器、摩擦、执行器与控制参数属于可审查的系统级设置；没有把这些参数声明为经过实物试验辨识。

据本次证据，v0.6 保留既有名义控制能力，并修正了失电供能、未供电传感器更新和缓冲器受力高度的物理边界。后续替换设备或改变质量、坡度、控制标定、采样周期及保护策略时，应针对实际改变的风险重新检查相应工况。
